## 1. 核心结论（先看这里）

Blackwell（sm_120）目前需要 **CUDA 12.8+ / 13.x 级别的工具链**，老的 `jax[cuda12]` 轮子编译时不含 sm_120 PTX，
装上去也只会回退 CPU。这一次能跑通的关键是两点：

1. 安装 **JAX 0.9.2 + jax-cuda12-plugin 0.9.2**，并通过 pip 拉齐 `nvidia-*-cu12` 12.9.x 系列运行时库；
2. **把 pip 安装的 nvidia 库目录加入 `LD_LIBRARY_PATH`**，否则 cuSPARSE 加载失败 → JAX 静默回退 CPU。

第 2 点是最容易踩、且最难发现的坑，详见第 3 节。

## 2. 安装步骤

```bash
# 1) 建环境
conda create -n relax_blackwell python=3.11 -y
conda activate relax_blackwell

# 2) 安装 GPU 版 JAX（会自动拉 nvidia-*-cu12 运行时依赖）
pip install -U "jax[cuda12]"

# 3) 项目依赖
cd /data/home/zch_zhou28/workspace/work2026/DPRL_V2/diffusion_policy_online_rl
pip install -r requirements.txt
pip install -e .            # 安装 relax 包本体（可编辑模式）
```

安装过程中缺什么补什么，本次实际额外补装过：`PyYAML`、`dm-haiku`、`gymnasium==1.0.0`、`mujoco`、`wandb`、`tensorboardX`。

> `requirements.txt` 里若写死了旧版本 jax/jaxlib，**不要**让它覆盖已装好的 0.9.2，
> 否则会把 GPU 版换成不支持 sm_120 的旧轮子。装完后务必回查 `pip list | grep jax`。

## 3. 最大的坑：cuSPARSE 加载失败导致静默回退 CPU

### 3.1 现象

`import jax` 时会打印如下报错，但**程序不会崩**，而是悄悄用 CPU 继续跑：

```
Jax plugin configuration error: Exception when calling jax_plugins.xla_cuda12.initialize()
RuntimeError: jaxlib/cuda/versions_helpers.cc:85: operation cusparseGetProperty(MAJOR_VERSION, &major) failed:
             The cuSPARSE library was not found.
RuntimeError: Unable to load cuSPARSE. Is it installed?
An NVIDIA GPU may be present on this machine, but a CUDA-enabled jaxlib is not installed. Falling back to cpu.
[CpuDevice(id=0)]
```

### 3.2 根因

`libcusparse.so.12` 文件其实是存在的，但它依赖的 `libnvJitLink.so.12` 找不到对应的版本化符号：

```bash
python -c "import ctypes; ctypes.CDLL('$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cusparse/lib/libcusparse.so.12')"
# OSError: .../libcusparse.so.12: undefined symbol: __nvJitLinkGetErrorLogSize_12_9,
#          version libnvJitLink.so.12
```

即 pip 安装的 `nvidia-cusparse-cu12` 与 `nvidia-nvjitlink-cu12` 分别装在各自的 `site-packages/nvidia/*/lib/` 目录下，
动态链接器默认不搜索这些路径，符号解析失败。

### 3.3 解决办法

把相关 nvidia 库目录加入 `LD_LIBRARY_PATH`：

```bash
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cusparse/lib:$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/nvjitlink/lib:$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cublas/lib:$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cudnn/lib:$LD_LIBRARY_PATH
```

### 3.4 让它永久生效（推荐）

`export` 只对当前终端会话有效，用 conda 的激活钩子做到「激活环境即生效」，配置一次即可：

```bash
conda activate relax_blackwell
mkdir -p $CONDA_PREFIX/etc/conda/activate.d $CONDA_PREFIX/etc/conda/deactivate.d

cat << 'EOF' > $CONDA_PREFIX/etc/conda/activate.d/env_vars.sh
export OLD_LD_LIBRARY_PATH=$LD_LIBRARY_PATH
export LD_LIBRARY_PATH=$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cusparse/lib:$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/nvjitlink/lib:$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cublas/lib:$CONDA_PREFIX/lib/python3.11/site-packages/nvidia/cudnn/lib:$LD_LIBRARY_PATH
EOF

cat << 'EOF' > $CONDA_PREFIX/etc/conda/deactivate.d/env_vars.sh
export LD_LIBRARY_PATH=$OLD_LD_LIBRARY_PATH
unset OLD_LD_LIBRARY_PATH
EOF
```

另一种做法是在启动脚本（如 [run.sh](../run.sh)）首行写上 `export LD_LIBRARY_PATH=...`，只保证脚本内生效。

## 4. 验证 GPU 是否真的启用

```bash
python -c "import jax; print(jax.devices())"
```

修复后应输出：

```
[CudaDevice(id=0), CudaDevice(id=1), CudaDevice(id=2), CudaDevice(id=3)]
```

若输出 `[CpuDevice(id=0)]`，说明仍在 CPU 上，回到第 3 节检查。

## 5. 训练启动方式

```bash
cd diffusion_policy_online_rl/zczhou
bash run.sh
```

`run.sh` 中的关键环境变量：

| 变量 | 作用 |
| --- | --- |
| `XLA_FLAGS='--xla_gpu_deterministic_ops=true'` | GPU 算子确定性，保证可复现 |
| `CUDA_VISIBLE_DEVICES=3` | 指定使用第 4 号卡（多人共用机器时按需改） |
| `XLA_PYTHON_CLIENT_MEM_FRACTION=.1` | 限制 JAX 预分配显存比例，避免独占整卡 |

## 6. 排查经验总结

1. **不要凭 wandb 的 `wandb-metadata.json` 判断是否用了 GPU。** 里面的 `gpu: NVIDIA GeForce RTX 5090`
   只是 wandb 探测到的宿主硬件，跟 JAX 实际算在哪儿无关。判断依据只有 `jax.devices()` 的输出。
2. **训练速度是最直接的信号。** 本次 CPU 误跑的实测：HalfCheetah-v4 SDAC（diffusion_steps=20,
   num_particles=32, num_vec_envs=5）约 65~66 分钟 / 5 万步（≈12.6 steps/s），15.78 小时才跑到 71.5 万步；
   GPU 上 100 万步应在小时级以内完成。跑一晚上没跑完就该怀疑设备。
3. **`import jax` 的报错不要忽略。** JAX 的 CPU 回退是静默的，唯一提示就是那几行 warning。
   建议在训练脚本入口加一行 `print(jax.devices())`，日志里留痕。
4. **evaluator 子进程显式设 `JAX_PLATFORMS=cpu` 是正常设计**（见 `relax/trainer/evaluator.py`），
   不是 bug，不要误改。
5. 若 `LD_LIBRARY_PATH` 仍不奏效，下一步排查方向是重装并对齐
   `nvidia-cusparse-cu12` 与 `nvidia-nvjitlink-cu12` 的版本组合。
