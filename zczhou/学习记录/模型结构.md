# SDAC / DPMD 模型结构与单次推理计算过程

本文所有形状、层数、算子计数都来自两个可验证来源，不是从配置推断的：

1. checkpoint 里的真实权重张量 `logs/HalfCheetah-v4/sdac_2026-09-01_05-18-24_s100_test_use_atp1/policy-1000000-200000.pkl`
2. 训练开始时导出的计算图 `deterministic.txt`（jaxpr 文本，即 `run_single_infer.sh` 实际执行的那张图）

环境为 `HalfCheetah-v4`，`obs_dim=17`，`act_dim=6`。

## 0. 单次推理逐层总表

下表按**实际执行顺序**列出一次 `env.step`（即一次动作决策）的全部计算。所有形状取自 jaxpr，`[32,...]` 的 32 是 `num_particles`，32 条候选动作全程并行。

| 阶段（执行次数） | 内部每一层 | 输入 -> 输出形状 | 简单说明 |
|---|---|---|---|
| **A. 采样初始化**（1 次） | `random_key_from_data(obs)` | `[17]` -> `key` | 用 obs 的 mean/std 派生种子，同一 obs 必得同一动作 |
| | `0.5 * normal(...)` | -> `[32,6]` | 扩散起点 `x_T`，注意有 0.5 缩放 |
| | `normal(...)` | -> `[32,20,6]` | 20 步所需的噪声一次性预生成 |
| **B. 时间编码支路**<br>（扩散内，20 次） | `scaled_sinusoidal_encoding` | `t` -> `[8]`+`[8]`=`[16]` | `sin`/`cos` 各 1 次后 concat |
| | `Linear(16 -> 32)` | `[16]` -> `[32]` | 权重 `linear` |
| | **mish** | `[32]` -> `[32]` | 唯一激活位置 |
| | `Linear(32 -> 16)` | `[32]` -> `[16]` | 权重 `linear_1`，**后面没有激活** |
| **C. 去噪主干**<br>（扩散内，20 次） | `concat(obs, x, te)` | `[17]+[32,6]+[16]` -> `[32,39]` | 39 = 17 + 6 + 16 |
| | `Linear(39 -> 256)` + **mish** | `[32,39]` -> `[32,256]` | 权重 `linear_2` |
| | `Linear(256 -> 256)` + **mish** | `[32,256]` -> `[32,256]` | 权重 `linear_3` |
| | `Linear(256 -> 256)` + **mish** | `[32,256]` -> `[32,256]` | 权重 `linear_4` |
| | `Linear(256 -> 6)` | `[32,256]` -> `[32,6]` | 权重 `linear_5`，输出噪声预测 `eps`，**无激活**（`output_activation=Identity`） |
| **D. 单步去噪更新**<br>（扩散内，20 次） | `x_recon = clip(x*srac[t] - eps*srm1[t], -1, 1)` | `[32,6]` -> `[32,6]` | 每步都 clip，不是只最后一次 |
| | `mean = x_recon*c1[t] + x*c2[t]` | `[32,6]` -> `[32,6]` | 4 个系数表均为内联 `float32[20]` 常量 |
| | `x = mean + (t>0)*sigma[t]*noise[:,t,:]` | `[32,6]` -> `[32,6]` | `t=0` 时不再加噪 |
| **E. Q 打分**（各 1 次，共 2 个 Q 网） | `concat(obs, act)` | `[17]+[32,6]` -> `[32,23]` | 23 = 17 + 6 |
| | `Linear(23 -> 256)` + **mish** | `[32,23]` -> `[32,256]` | 权重 `linear` |
| | `Linear(256 -> 256)` + **mish** | `[32,256]` -> `[32,256]` | 权重 `linear_1` |
| | `Linear(256 -> 256)` + **mish** | `[32,256]` -> `[32,256]` | 权重 `linear_2` |
| | `Linear(256 -> 1)` + squeeze | `[32,256]` -> `[32]` | 权重 `linear_3`，**无激活** |
| **F. 选优与输出**（1 次） | `minimum(q1, q2)` | `[32]`,`[32]` -> `[32]` | clipped double Q |
| | `argmax` | `[32]` -> `[]` | 挑出得分最高的那条候选 |
| | 索引取动作 | `[32,6]` -> `[6]` | |
| | `act + normal([6]) * exp(log_alpha) * 0.1` | `[6]` -> `[6]` | `log_alpha` 被覆盖为 `-inf`，`exp=0`，噪声归零，见 §6 |
| | `clip(-1, 1)` | `[6]` -> `[6]` | 外层 `policy_fn` 再夹一次 |

读表要点：

- **B/C/D 三段在同一个 `scan` 里，重复 20 次**（jaxpr `length=20`），是串行依赖，无法并行；E/F 只在 20 步全部结束后执行一次。
- **激活不是每层都有**。时间编码支路的第二个 Linear、主干末层、Q 网末层都没有激活。用「每个 Linear 后面都跟 mish」来理解是错的。
- mish 总数：主干支路每步 4 次（B 段 1 + C 段 3）x 20 步 = 80 次，Q 网 3 x 2 = 6 次。
- `hidden_num=3` 指隐层数量，`mlp` 会额外补一个输出层，所以主干和 Q 网都是 **4 个 Linear**。

## 1. 一次推理到底在算什么

`run_single_infer.sh` 走的链路里没有 Python 侧的网络定义参与。`single_infer.py` 只做两件事：用 `PersistFunction.load` 把 `deterministic.pkl` 里的 jaxpr 反序列化成可调用函数，再把 `policy-*.pkl` 的参数喂进去。

```61:64:relax/trainer/evaluator.py
    policy = PersistFunction.load(args.policy_root / "deterministic.pkl")
    @jax.jit
    def policy_fn(policy_params, obs):
        return policy(policy_params, obs).clip(-1, 1)
```

被导出的是 `get_deterministic_action`：

```244:248:relax/algorithm/sdac.py
    def get_deterministic_action(self, policy_params: hk.Params, obs: jax.Array) -> jax.Array:
        params, log_alpha, q1_params, q2_params = policy_params
        act = self._get_deterministic_action(params, log_alpha, q1_params, q2_params, obs)
        return jnp.asarray(act)
```

所以 **单步推理不是一次前向，而是「20 步扩散采样 x 32 条并行候选 + Q 网打分选优」**。单个 `env.step` 背后：策略网跑 20 次（scan），Q 网跑 2 次（q1/q2 各一次，batch=32）。

对应 jaxpr 里的证据：`scan` 的 `length=20`，carry 形状 `[32,6]`。

## 2. 有哪几个模型

`policy-*.pkl` 是一个 4 元组，与 `get_deterministic_action` 的解包顺序一致：

| 位置 | 内容 | 推理时是否参与 | 参数量 |
|---|---|---|---|
| 0 | `target_policy`（DACERPolicyNet） | 参与，scan 内每步一次 | 144,438 |
| 1 | `log_alpha` | **不参与**，确定性路径把它覆盖为 `-inf`，见 §6 | 1 |
| 2 | `q1`（QNet） | 参与，给 32 个候选打分 | 137,985 |
| 3 | `q2`（QNet） | 参与，同上 | 137,985 |

合计 420,409 个参数。注意推理用的是 **target policy** 而非 online policy，这是 `deterministic.pkl` 导出时就固定的。

Critic 在推理阶段并没有被丢掉——它承担「从 32 个候选动作里挑最优」的职责，这是 SDAC 这类方法和普通 diffusion policy 的一个显著区别。

## 3. 每个模型的尺寸

### 3.1 策略网 DACERPolicyNet

配置来自 `default_cfg.json`：`hidden_num=3`，`hidden_dim=256`，`diffusion_steps=20`，`num_particles=32`。

时间步编码分支（正弦编码 -> 两层 MLP）：

| 层 | 形状 | 说明 |
|---|---|---|
| `linear`（w/b） | `[16, 32]` / `[32]` | 输入是 16 维正弦编码 |
| `linear_1`（w/b） | `[32, 16]` / `[16]` | 输出 16 维时间嵌入 |

主干（`mlp` 实际是 3 个隐层 + 1 个输出层，共 4 个 Linear）：

| 层 | 形状 | 说明 |
|---|---|---|
| `linear_2` | `[39, 256]` | 输入 39 = obs 17 + act 6 + time_emb 16 |
| `linear_3` | `[256, 256]` | |
| `linear_4` | `[256, 256]` | |
| `linear_5` | `[256, 6]` | 输出噪声预测，维度 = act_dim |

这里有个容易踩的点：`hidden_num=3` 指的是隐层数量，`mlp` 会额外加一个输出层，所以是 4 个 Linear 而不是 3 个。

```20:31:relax/network/blocks.py
def mlp(hidden_sizes, output_dim, activation=jax.nn.relu, output_activation=None):
    layers = []
    for hidden_size in hidden_sizes:
        layers.append(hk.Linear(hidden_size))
        layers.append(activation)
    layers.append(hk.Linear(output_dim))
```

### 3.2 Q 网 QNet

结构比策略网简单，没有时间条件分支：

| 层 | 形状 | 说明 |
|---|---|---|
| `linear` | `[23, 256]` | 输入 23 = obs 17 + act 6 |
| `linear_1` | `[256, 256]` | |
| `linear_2` | `[256, 256]` | |
| `linear_3` | `[256, 1]` | 标量 Q 值，输出后 squeeze |

q1 与 q2 结构完全相同，只是初始化不同，构成 clipped double Q。

## 4. 扩散过程

反向扩散 20 步，从 `t=19` 递减到 `t=0`。起点是 `x_T = 0.5 * normal([32, 6])`（注意有 0.5 缩放，不是标准正态）。

每一步在 `scan` 体内做：

```
eps      = policy_net(obs, x, t)                 # 噪声预测
x_recon  = clip(x * srac[t] - eps * srm1[t], -1, 1)
mean     = x_recon * c1[t] + x * c2[t]
x        = mean + (t > 0) * sigma[t] * noise[:, t, :]
```

四个系数表 `srac / srm1 / c1 / c2` 都是预先算好的 `float32[20]` 常量，直接内联在 jaxpr 里，推理时只是查表。beta 用线性 schedule，`scale=0.8`。

`x_recon` 那步的 `clip(-1, 1)` 值得留意：它在**每一步**都把重建结果夹到动作范围内，而不是只在最后夹一次。这是 DDPM 常见的稳定化技巧。

最后一步 `t=0` 时 `(t > 0)` 为假，不再加噪，输出确定性结果。

## 5. 非线性步骤清单

从 jaxpr 逐个统计，推理图里的非线性只有这几类：

| 非线性 | 出现位置 | 次数 |
|---|---|---|
| `mish` | 策略网 scan 体内 | 每步 4 次（时间编码 1 + 主干 3），20 步共 80 次 |
| `mish` | Q 网 | 每个 Q 网 3 次，q1+q2 共 6 次 |
| `sin` / `cos` | 时间步正弦编码 | 每步各 1 次 |
| `clip`（min/max） | x_recon、最终动作、外层 policy_fn | 见上文 |
| `minimum` | `min(q1, q2)` | 1 次 |
| `argmax` | 选最优 particle | 1 次 |
| `exp` | `exp(log_alpha)` | 1 次 |

激活函数是 **mish**（`x * tanh(softplus(x))`），不是 relu：

```105:112:relax/network/blocks.py
class DACERPolicyNet(hk.Module):
    def __init__(self, hidden_sizes: Sequence[int], activation: Callable = jax.nn.mish):
```

**推理图里没有 softmax，也没有 logsumexp。** 我在 jaxpr 里搜过 `softmax / logsumexp / reduce_max / logistic / erf`，命中数均为 0。`logsumexp` 只出现在 SDAC 训练的 policy loss 里（`relax/algorithm/sdac.py:159`，用于对 64 个候选做 softmax 加权，见 §7），导出的确定性推理图完全不含。

`mish` 在 jaxpr 里是**展开**的，不是单个算子。每次 mish 对应一组 `exp -> log1p -> tanh -> mul`（即 `x * tanh(softplus(x))` 的字面展开），所以图里能直接数到 10 个 `tanh`：策略网 scan 体内 4 个 + Q 网 3 个 x 2 = 10，与 §5 表格的计数自洽（scan 体内的 4 个在图文本里只出现一次，运行时重复 20 遍）。

## 6. 一个反直觉的细节：log_alpha 与随机性

推理图里其实**有** RNG 算子，但最终结果是确定的，原因有两层。

第一，随机种子不是外部传入的，而是从 obs 自身派生：

```78:83:relax/network/diffv2.py
    def get_deterministic_action(self, policy_params: hk.Params, obs: jax.Array) -> jax.Array:
        key = random_key_from_data(obs)
        policy_params, log_alpha, q1_params, q2_params = policy_params
        log_alpha = -jnp.inf
        policy_params = (policy_params, log_alpha, q1_params, q2_params)
        return self.get_action(key, policy_params, obs)
```

jaxpr 里可以看到 obs 的 mean 与 std 相乘后 bitcast 成整数当种子。同样的 obs 必然得到同样的 key，所以同一状态下动作可复现。

第二，`get_deterministic_action` 与 `get_action` 共用同一套采样代码，末尾都有探索噪声：

```62:62:relax/network/diffv2.py
        act = act + jax.random.normal(noise_key, act.shape) * jnp.exp(log_alpha) * self.noise_scale
```

区别在于上面第 81 行把 `log_alpha` **硬覆盖成 `-jnp.inf`**，于是 `exp(-inf) = 0`，噪声项整体归零。

这里有个容易误判的点：checkpoint 里存的 `log_alpha` 实际是 `-0.01606`（`exp` 约 0.984，是个相当大的噪声系数），并**不是** `-inf`。是代码在确定性路径上丢弃了这个值。所以导出的 jaxpr 里固化的是 `-inf`，训练时的 `get_action` 才会真正用到 checkpoint 里的温度值。

这解释了为什么之前实测同一 checkpoint、同一 seed 反复跑，`ep_ret` 能逐位复现 11841.96。

## 7. SDAC 与 DPMD 的差异

**网络主体完全相同**，两者都调用同一个 `create_diffv2_net`，共用 `relax/network/diffv2.py` 里的 `DiffV2Net`、同一套 `Diffv2Params`、同一个 `get_deterministic_action`。所以 §3 的所有尺寸、§5 的所有非线性、`deterministic.pkl` 的结构对两者完全一致。

Q 网的更新也一样（都是 `mean((q - q_backup)^2)` + clipped double Q），`log_alpha` 的自适应温度 loss 更是逐字相同：

```147:150:relax/algorithm/dpmd.py
            def log_alpha_loss_fn(log_alpha: jax.Array) -> jax.Array:
                approx_entropy = 0.5 * self.agent.act_dim * jnp.log( 2 * jnp.pi * jnp.exp(1) * (0.1 * jnp.exp(log_alpha)) ** 2)
                log_alpha_loss = -1 * log_alpha * (-1 * jax.lax.stop_gradient(approx_entropy) + self.agent.target_entropy)
                return log_alpha_loss
```

真正的差异**只在 policy loss 的加权方式**这一处：

| 维度 | DPMD | SDAC |
|---|---|---|
| 加权目标 | 对**采样出的真实动作** `next_action` 做去噪回归 | 对**反向重建动作** `recon` 做回归 |
| 权重来源 | `exp(clip(归一化Q, -3, 3) / alpha)`，全 batch 直接指数 | 每个状态采 `reverse_mc_num=64` 个候选，用 `logsumexp` 归一化后再 `exp` |
| 权重归一化 | 无归一化，靠 clip 防爆 | `exp(q - logsumexp(q))`，即每个状态内部做 **softmax** |
| 单次更新成本 | batch 一份前向 | batch x 64 份前向 |
| loss 函数 | `diffusion.weighted_p_loss` | `diffusion.reverse_samping_weighted_p_loss` |

关键行对比。DPMD：

```132:134:relax/algorithm/dpmd.py
                scaled_q = norm_q.clip(-3., 3.) / jnp.exp(log_alpha)
                q_weights = jnp.exp(scaled_q)
```

SDAC：

```159:160:relax/algorithm/sdac.py
                Z = jax.nn.logsumexp(q_reshape, axis=1, keepdims=True) # [batch_size, 1]
                q_weights = jnp.exp(q_reshape - Z).flatten() # [batch_size, mc_num]
```

所以 SDAC 可以理解为「在 DPMD 的 advantage 加权基础上，改成对每个状态的 64 个反向采样候选做 softmax 加权」，本质上是用蒙特卡洛把加权目标估得更准，代价是训练时算力涨了 64 倍。这也是 §5 里提到的 softmax / logsumexp 的唯一出处——**只在 SDAC 训练时，推理图里没有**。

结论：**只看单次推理，SDAC 和 DPMD 的计算图完全没有区别**，差异只体现在权重数值上。`single_infer.py` 无需任何改动就能加载 DPMD 的 checkpoint。

## 8. 计算量粗估

单个 `env.step` 的乘加规模（不含 bias，batch=32）：

- 策略网单步：时间编码 `16*32 + 32*16 = 1024`，主干 `39*256 + 256*256 + 256*256 + 256*6 = 143,878`，合计约 144.9K，乘以 batch 32 约 4.64M
- 20 个扩散步：约 92.7M
- Q 网两个：`(23*256 + 256*256 + 256*256 + 256*1) * 32 * 2` 约 8.8M

单步决策合计约 1.0 亿次乘加。一个 1000 步 episode 约 1000 亿次。这解释了为什么完整 rollout 在 CPU 上要十几秒——瓶颈是 20 步扩散的串行依赖，无法并行掉。
