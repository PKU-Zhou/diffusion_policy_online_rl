# 训练过程中的关键概念辨析


| 概念          | 含义                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------ |
| episode     | 一个完整的交互序列,从环境reset开始,到terminated(任务完成)或truncated(超时)结束                                           |
| iteration   | 训练的一次迭代,包含sample和update两个阶段。每次迭代执行 `sample_per_iteration` 次采样和 `update_per_iteration` 次更新(默认都是1) |
| sample_step | 与环境交互的总次数。对于向量化环境,一次step可能同时在多个环境中执行                                                             |
| update_step | 网络参数更新的总次数。每次update从buffer中采样一个batch进行梯度更新                                                       |
| stage       | 训练的两个主要阶段: **sample阶段**(与环境交互收集数据) 和 **update阶段**(从buffer采样并更新网络)                                |


# 训练过程详细分析

## 整体流程概览

训练过程由 `OffPolicyTrainer` 类的 `train` 方法控制,主要分为以下阶段:

```
初始化 → Warmup → 训练主循环(Sample → Update → 评估/保存) → 结束
```

## 各阶段详细说明

### 1. 初始化阶段 (`setup` 方法)

在训练开始前执行一次:

1. **算法预热**: 调用 `algorithm.warmup(dummy_data)` 预热JAX的JIT编译
2. **日志初始化**: 创建TensorBoard日志writer和进度条
3. **保存网络结构**:
  - 保存策略网络结构 (`save_policy_structure`)
  - 保存Q网络结构 (`save_q_structure`)
4. **启动评估器**: 启动一个独立的Python子进程用于异步评估策略



### 2. Warmup阶段 (`warmup` 方法)

目的: 在开始训练前填充经验回放buffer

- **执行条件**: 持续到 `len(buffer) >= start_step` (默认30000步)
- **动作选择**: 
  - `warmup_with="random"`: 使用随机动作(默认)
  - `warmup_with="policy"`: 使用当前策略
- **数据收集**: 与环境交互,收集 (obs, action, reward, terminated, truncated, next_obs) 存入buffer
- **环境重置**: 当episode结束(terminated或truncated)时,重置环境



### 3. 训练主循环 (`train` 方法)

**循环条件**: `sample_step <= total_step` (默认训练到1M步)

**每次迭代**包含两个阶段:

#### 3.1 Sample阶段 (`sample` 方法)

执行 `sample_per_iteration` 次(默认1次):

1. **生成随机密钥**: 使用JAX的随机数生成器为每次采样生成独立的key
2. **策略推理**: `action = algorithm.get_action(sample_key, obs)`
  - 对于扩散策略,这涉及多步去噪过程
  - 输入当前观测,输出要执行的动作
3. **环境交互**: `next_obs, reward, terminated, truncated, info = env.step(action)`
  - 如果是向量化环境,同时在多个环境中执行
4. **经验存储**: 将 `Experience(obs, action, reward, terminated, truncated, next_obs)` 存入buffer
5. **日志记录**: 累积reward,统计episode长度
6. **Episode结束处理**:
  - 如果任何环境的episode结束,记录该episode的统计信息
  - 每隔 `sample_log_n_episode` 个episode,将统计信息写入日志
  - 重置已结束的环境



#### 3.2 Update阶段 (`update` 方法)

执行 `update_per_iteration` 次(默认1次):

1. **生成随机密钥**: 为每次更新生成独立的key(用于随机采样和dropout等)
2. **采样batch**: `data = buffer.sample(batch_size)` (默认256)
  - 从buffer中均匀随机采样一个batch的经验
3. **网络更新**: `info, dist_info = algorithm.update(update_key, data)`
  - 计算损失函数(Q损失、策略损失、熵正则化等)
  - 反向传播计算梯度
  - 使用优化器更新网络参数
  - 可能包括目标网络的软更新
4. **日志记录**: 每隔 `update_log_n_step` 步(默认1000),记录损失和其他训练指标



### 4. 评估和保存

**策略保存** (每隔 `save_policy_every` 步,默认total_step/20):

- 保存策略网络参数到pickle文件
- 保存Q网络参数(如果 `save_value=True`)
- 文件名格式: `policy-{sample_step}-{update_step}.pkl`

**策略评估** (异步进行):

- 每次保存策略后,向评估器子进程发送命令
- 评估器在独立进程中运行策略并记录性能
- 结果写入单独的日志文件



### 5. 训练结束 (`finish` 方法)

1. 关闭环境
2. 保存最终的算法状态到 `state.pkl`
3. 记录超参数
4. 关闭日志writer和进度条
5. 终止评估器子进程



## 关键实现细节



### 随机数管理

- 使用JAX的函数式随机数生成器,通过 `jax.random.fold_in` 为每个step生成独立的key
- 保证可复现性的同时避免状态管理



### 向量化环境支持

- 如果使用向量化环境 (`num_vec_envs > 0`),一次step同时在多个环境中执行
- Sample阶段效率提升,但单次step的计算量也相应增加



### 异步评估

- 评估在独立进程中进行,不阻塞训练
- 通过stdin/stdout进行进程间通信
